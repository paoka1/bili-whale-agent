## 日记分层记忆 + 目录索引（2026-10-29 提出，未开始）

**为什么**：每次醒来 `diary_read` 读两本日记全文、`diary_write` 整篇覆盖重写。2026-10-29 实测两本共 12210 字，只写了约一天半：

- 按这个速度约两周撞上 `writeDiary` 的 200KB 上限（一个汉字 3 字节，约 6.8 万字），之后她就写不了日记。
- 日记越长每次醒来越贵（读进上下文 + 整篇重新输出），重写时也越容易漏掉旧段落，记忆永久丢失。
- 私人日记每篇都重复一段「偏好校准」「待办」；公开日记把按日期的正文和长期清单（看过 / 想说 / 谁回过我）混在一起。

**怎么改**：

1. 日记改为按天追加：新工具 `diary_append({ which, markdown })`，不再整篇重写。文件名不变（`whale-diary.md` / `whale-diary-private.md`），网页显示和选题排除看过的 BV 不受影响。
2. 新增「长期记忆」本（≤3000 字，如 `whale-memory.md`）：她用 `memory_write` 整篇覆盖维护，只放要长期记住的结论——主人口味、偏好校准结论、在跟进的待办、谁回过她。
3. `diary_read` 不再返回全文，只返回：长期记忆 + 最近 3 天的日记 + 目录（每篇一行：日期、标题、提到的 BV）。
4. 新增 `diary_search({ query })`：按关键词 / BV / 日期翻旧日记。
5. 不用向量检索：日记量不大，关键词 + 目录够用，也不用另配 embedding 接口。
6. 迁移：现有日记按 `## 日期 · 时段` 标题拆成条目；最新的「偏好校准」「待办」「看过」「想说」「谁回过我」整理成长期记忆的初始内容。

**改动范围**：`packages/bili` 的日记模块、工具层（`diary_append` / `memory_write` / `diary_search`，`diary_write` 去掉或只留给迁移）、唤醒提示词第 1 步和第 6 步、迁移脚本。网页暂不改（以后日记很长时，日记页可按日期分页）。
