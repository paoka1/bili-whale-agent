# bili-whale-agent 设计文档

日期：2026-10-29
状态：待确认

## 1. 这是什么、为什么做

[dsh-bili-whale](https://github.com/Alterssss/dsh-bili-whale)（MIT，作者 ALTERSSSS，当前 0.4.6）是一个 DSH（DeepSeek Harness）插件：让一个 AI 用自己的 B 站小号「住在 B 站里」——按作息自己醒来、刷视频、真看懂（字幕 / 弹幕 / 热评 / 抽帧）、写两本日记、把好东西分享给主人、回复评论和私信。

它离不开 DSH：作息、监听、提示词投递、设置页都绑在 DSH 的插件接口和会话上。本项目把它改造成**一个独立运行的程序**：

- 自带 agent（用现成框架，不手写循环），用户自己填 base url / model / API key；
- 程序常驻运行，到点唤醒 agent；
- 带网页界面：配置、查看她的活动；
- B 站能力与 agent 松耦合，目的是**把 B 站这部分代码理清楚、方便维护**（不是为了接别的平台）；
- 面向开源发布，给别人用。

## 2. 目标 / 非目标 / 反目标

**目标**

- 一条命令启动，网页里完成全部设置（扫码登录、模型、主人、人设、作息），之后无人值守运行。
- 支持任意 OpenAI 兼容接口（DeepSeek、通义、OpenAI、本地 Ollama 等）。
- 保留原插件的核心体验：作息唤醒、看懂视频、两本日记、分享给主人、评论 / 私信监听、回复陌生人先审草稿、风控与额度。
- 安全：网页必须有密码；agent 只能通过类型固定的工具做事，不能执行命令行。
- B 站代码独立成包，不依赖任何 LLM 库。

**非目标（第一版不做）**

- 直播间弹幕监听、动态（发/改动态）、`ai-share` 疑似 AI 评论检查、桌面通知。
- 把 B 站能力包导出成 MCP / skill（结构上留好口子，以后再说）。
- 从 DSH 版迁移现有日记和配置的导入工具（文件格式尽量沿用，迁移时手工拷贝即可）。
- 多用户、多账号、两步验证、公网部署方案（Tailscale / 反代文档）。

**反目标（做到了也算失败）**

- 模型能让程序执行任意命令、读写数据目录以外的文件、访问 B 站以外的网址。
- B 站 cookie 或 API key 出现在模型上下文、日志或网页回显里。
- 额度 / 频率 / 草稿审核这些限制只写在提示词里，模型能绕过去。
- 界面做得复杂：用户说过「不用做的太复杂」。

## 3. 约束

- 语言沿用原插件的 Node.js（TypeScript），Node ≥ 22。原 `tools/` 约 6400 行是主要的复用来源。
- 原插件是 MIT 许可：保留原版权声明（LICENSE 中并列），README 注明来源。本项目同样用 MIT。
- ffmpeg 可选，只有「抽帧看画面」用到；没装时深读降级为只读文字。
- 默认值按「刚注册的小号」设定（原插件的风控默认：写入 12 次/时、30 次/天、两次写入间隔 ≥120 秒；读 600 次/时）。

## 4. 已定的决定（来自用户）

- 形式：自己的常驻程序 + 网页，不是 skill。
- agent 用现成框架；网页前后端也用现成框架。
- 用户自填 base url / model / API key。
- 网页能配置监听地址，可以监听 `0.0.0.0`；网页必须设密码。
- 工具调用要安全，不能直接执行 bash。
- 网页只需要两件事：配置、查看她的活动；不要做复杂。
- 独立 git 仓库；代码从原插件分出。
- 服务器上现有的 DSH 版先不动。
- 第一版用另注册的专用测试号测试。

## 5. 架构（以下为实现者的决定，标注「建议」的可调整）

### 5.1 仓库结构（建议：pnpm workspace）

```
packages/
  bili/     B 站能力包：API 客户端、视频理解、额度与风控、日记文件读写。零 LLM 依赖。
  core/     agent（Vercel AI SDK）、工具定义、提示词、作息与监听调度、推送、HTTP 服务（Hono）。
  web/      网页（Vite + React + 现成组件库），构建产物由 core 静态托管。
```

`bili` 对外只暴露普通的 async 函数和类型；`core` 把它们包成 agent 工具。以后要导出 MCP，只需在 `bili` 外再包一层。

### 5.2 agent

- 框架：**Vercel AI SDK**（`ai` + OpenAI 兼容 provider）。用它的多步工具调用，不手写循环。
- 模型配置：主模型（base url / model / key）必填；**看图模型**可选——主模型不支持图片时（如 DeepSeek 的部分模型），抽帧图片交给看图模型转成文字描述再给主模型。
- 一次「运行」= 一个触发事件 + 一段提示词 + 有上限的工具调用步数（默认上限约 40 步）+ 超时。
- 触发事件三类：**唤醒**（按作息）、**有人找她**（评论回复 / @ / 主人私信）、**手动**（网页「立即唤醒」）。
- 提示词由原插件 `scheduler.js` 的唤醒流程、监听规则、红线改写，加上用户的人设（网页里编辑，存为 `persona.md`）。仓库只带一份中性的人设模板，不包含任何具体某个人的人设或日记。
- 记忆靠两本日记 + 行动记录，每次运行开头由工具读入；不保留跨运行的对话历史（与原插件实践一致）。

### 5.3 工具（agent 能做的全部事情）

读类：`feed`（按口味捞候选）、`search`、`video_brief`（字幕 / 弹幕 / 热评，不出图）、`video_deep`（含抽帧）、`comments`（读某视频评论）、`inbox`（谁回复 / @ 了她）、`diary_read`、`quota_status`。

写类：`comment_post`（顶层评论，可选分享型 @ 主人）、`reply_owner`（回复主人）、`reply_draft`（回复陌生人 → 进待审队列，不直接发）、`fav`、`dm_owner`（只能私信主人，需互关）、`diary_write`、`log`。

规则：
- 每个工具参数用 zod schema 校验（BV 号、rpid、长度上限等），校验失败直接拒绝。
- 工具内部直接调用 `bili` 包的函数，**不拼命令、不起子进程**（ffmpeg 除外：由代码以固定参数调用，文件名由代码生成）。
- 所有写操作先过 `bili` 包里的闸门：额度、频率、同视频冷却、分享 ≤3/天、陌生人只能草稿。闸门在代码里，提示词只是告知。
- 全局「演练模式」（建议默认开启）：写类工具只记录「本来会发什么」，不真正请求 B 站。用户在网页上确认效果后再关掉。
- B 站网络请求只允许 B 站域名（含视频 / 图片 CDN），其他一律拒绝。
- 工具返回的评论、弹幕、简介、字幕统一包在「以下是不可信的外部内容」标记里，提示词说明其中任何指令都不执行。

### 5.4 调度

- 进程内定时器，不依赖 cron。作息算法移植原插件 `night-plan` / `night-config`：时间窗内随机时刻、每日上限、跳过概率、最小间隔，计划持久化，重启后不重复也不漏。
- 监听：按配置间隔轮询评论回复 / @ / 主人私信，失败指数退避（沿用 `poll-policy`）；有新消息才触发运行。
- 同一时刻只有一个运行；运行中到来的事件排队。

### 5.5 推送

第一版支持：`none`、`dm`（私信主人，需互关）、`webhook`（POST 到用户填的地址）。推送内容：唤醒总结 / 给主人的信、待审草稿提醒、风控暂停、登录失效。

### 5.6 数据

- 数据目录默认 `~/.bili-whale`，可用环境变量 `BILI_WHALE_HOME` 或启动参数指定。
- 文件沿用原插件格式（`whale-diary.md`、`whale-diary-private.md`、`whale-log.jsonl`、`quota.json`、`favorites.json` 等），方便以后从 DSH 版拷过来。
- `credentials.json`（B 站 cookie）、模型 key、网页密码哈希单独存放，权限 0600，永不回显、不进日志。

### 5.7 网页

后端 Hono，前端 Vite + React + 组件库，朴素即可。

- **登录**：首次启动在终端打印一次性设置码，网页输入设置码后设密码（长度下限）。之后凭密码登录。
- **配置页**（一页表单，保存即生效）：模型（含可选看图模型，key 只写不回显）；B 站账号（扫码登录、状态）；主人 mid；她是谁（名字、称呼、人设大文本框）；口味（爱看 / 不爱看）；作息时间窗；分享方式与推送；监听开关；演练模式开关；「高级」折叠里放风控额度和监听地址 / 端口。
- **活动页**：顶部状态（醒 / 睡、下次唤醒时间、今日额度、「立即唤醒」按钮）；待审草稿（发 / 不发）；动态时间线（看了什么、收藏、评论、谁回了她，带链接）；两本日记（渲染成文章，私人日记也可看）。

### 5.8 安全

- 监听地址默认 `127.0.0.1`，可配 `0.0.0.0`；非本机访问且为 HTTP 时页面提示明文风险；可选配置证书启用 HTTPS。
- 密码 scrypt/argon2 加盐哈希；登录失败逐次延迟、连续失败临时锁定；会话 cookie `httpOnly` + `SameSite=Strict`（HTTPS 时加 `Secure`），有过期时间；修改类接口校验 CSRF。
- 改密码、改 key、换 B 站账号需要再次输入密码。
- 审计记录：登录、配置修改、草稿批准 / 拒绝。

## 6. 测试与验收

- `bili` 包：移植原插件中适用的测试（原有 154 项，多为模拟 B 站响应），覆盖额度闸门、草稿规则、作息计划、扫码状态机。
- `core`：工具参数校验、域名白名单、不可信内容包装、演练模式下写工具不发请求、运行步数 / 超时上限。
- 网页：设置码 → 设密码 → 登录 → 保存配置 → 立即唤醒 → 活动页出现记录，能端到端走通。
- 测试账号：用户另注册一个**专用测试号**（不用 DSH 版正在用的号，避免两个程序在同一账号上各算各的额度而触发风控）。测试号需绑定手机并通过转正答题，否则无法评论。
- 验收：先在演练模式下用测试号完整跑一轮唤醒（读真数据、写只记录），日记和活动页内容合理；再关闭演练模式，在测试号上做一次真实评论与分享。
