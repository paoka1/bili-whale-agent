# 日记分层记忆与迁移设计

日期：2026-10-30
状态：实现前方案，代码未开始

需求来源：`docs/TODO.md`「日记分层记忆 + 目录索引」。实现步骤见 `docs/superpowers/plans/2026-10-30-diary-memory.md`。

## 1. 为什么改

现在 `packages/bili/src/diary.ts` 的 `readDiaries` 读两本全文，`writeDiary` 整篇原子覆盖，单本限制 200KB。`packages/core/src/tools.ts` 把全文交给模型，唤醒第 6 步又要求模型延续原文、整篇写回。正文越长，上下文与输出越贵，也越容易漏掉旧内容。

另有两处直接消费旧文件：网页 `GET /api/diaries` 返回两本全文；`feed.ts` 扫描两本全文中的 BV 排除看过的视频。分层后保留它们的行为。

## 2. 范围与约定

- 长期记忆放结论，日记放经历，目录与关键词搜索负责找回旧经历。不接 embedding，不加数据库、不调用额外模型。
- 保留 `whale-diary.md` / `whale-diary-private.md`，历史正文不改写、不删除；同一天可以追加多篇。
- `packages/bili` 继续只做本地文件与普通函数；agent 工具、zod schema 和不可信包装留在 `packages/core`。
- 沿用现有「只在边界校验」「测试从简」：工具输入在 schema 校验，本地文件在读取时处理格式；内部函数信任类型。
- 网页日记页与 HTTP 返回形状暂不改，只补新工具的中文活动名称。全文扫描与网页全文加载的性能优化留到确有需要时。
- 本次迁移是当前数据目录内的日记升级，不是 DSH 配置、账号、人设的通用导入器。

## 3. 文件与分层

| 文件 / 内容 | 用途 | 写入方式 |
|---|---|---|
| `whale-memory.md` | 主人口味、偏好校准结论、仍在跟进的待办、重要互动关系 | `memory_write` 整篇原子覆盖，最多 3000 字 |
| 两本日记最近 3 个自然日 | 本轮需要接上的具体经历与感受 | `diary_append` 只追加本轮正文 |
| 两本日记全部条目的目录 | 日期、标题、提到的 BV、定位 ID | 从原文件解析，不另存索引文件 |
| 两本日记历史正文 | 搜索、按条目回读、网页全文展示 | 保留原文 |

「3000 字」按 Unicode 码点计数（`Array.from(text).length`），包括标题、标点与换行；超限拒绝，旧内容保持原样，要求她先压缩结论。不能静默截断记忆。记忆只保存文字，不改变配置文件、主人身份或工具权限。

目录先按需解析：当前规模下读文件、线性扫描已经够用，也省去正文与索引双写、崩溃恢复、索引过期的问题。这里只减少交给模型的内容，不承诺常数时间的磁盘读取。

## 4. 日记条目与追加

新工具仍是 TODO 提出的 `diary_append({ which, markdown })`。`which` 为 `public` / `private`，`markdown` 只交本轮正文；程序用 `ctx.now()` 和进程本地时区生成标题：

```markdown
## 2026-10-30 · 21:30

今晚看了……
```

- 日期与现有作息、额度保持同一个服务器时区，不能用 `toISOString().slice(0, 10)` 划自然日。工具回读同时告知当前日期与时区。
- 单次追加的 UTF-8 正文最多 20KB，不能为空；拒绝正文在代码围栏外自带 `## 日期 · 时段` 条目标题，避免一笔写入伪造多个条目。普通 Markdown 小标题、表格、代码块照常允许。
- 追加时补必要的空行，用一次同步 `appendFileSync` 写入完整的标题与正文；首次创建文件权限 0600。总文件不再受原来的 200KB 限制。
- 不用「读全文 → 拼接 → 重写」实现追加。一次调用成功后返回 `{ ok: true, entry }`，模型不再重发旧段落。
- 沿用调度器同一账号串行运行的约定，不加多进程锁；命令报错不能自动重试追加，先读末条确认是否已写入。
- 原 `writeDiary` 只保留为内部兼容函数（现有测试、手工维护可继续用），不再作为 agent 工具暴露；它原有的 200KB 限制不影响追加路径。

同一解析函数用于近期阅读、目录、搜索和迁移。按代码围栏外的二级日期标题 `## YYYY-MM-DD · …` 切条目，兼容标题两侧空白；正文内的三级小标题不切条目。保留每段原文，不重排、不重渲染 Markdown。

标题前的序言、无日期的旧正文都保留为「未标日期」条目；非法日期也归入这一类，不冒充今天。条目 ID 用 `public:0` / `private:0` 这样的「日记类型 + 段落序号」，在只追加、不改历史的约定下保持稳定。目录标题取日期标题后面的文字；无日期条目用首行摘要，最多 60 字。

## 5. 阅读、目录与搜索

内部仍保留 `readDiaries(dataDir)` 返回 `{ public, private }` 给网页和兼容调用。另加给 agent 用的读取函数，不改变现有 HTTP 接口。

### 5.1 `diary_read`

保留 `diary_read({})` 的唤醒入口，并增加两种按需回读形式：

| 参数 | 返回内容 |
|---|---|
| `{}` | 长期记忆、最近 3 天正文、第一页目录、当前日期与时区 |
| `{ catalogOffset }` | 下一页目录，不重复返回记忆和近期正文 |
| `{ entry, offset? }` | 指定条目的正文片段，按字符偏移继续读 |

工具 schema 用互斥形状区分三种调用，不允许混传。偏移必须为非负整数；未知条目明确返回未找到，不能回退为全文。

- 最近 3 天指今天、昨天、前天，包含两本日记中的所有时段；按日期筛选，不是最后 3 篇，也不是滚动 72 小时。
- 默认近期正文两本合计最多 24000 字，优先保留最新条目，返回时按时间先后排列；单篇旧文过长时只给可容纳的片段。省略或截短必须标明条目 ID、剩余内容可用 `diary_read({ entry, offset })` 回读。
- 每页目录最多 100 条，按日期从新到旧，同日按文件顺序从后往前；未标日期的排最后，跨本同日以公开、私人固定排序。包含 `entry`、`which`、`date`、标题及 BV；显示每条最多 10 个 BV，更多时给出总数，搜索仍匹配全部 BV。
- 目录返回总条数与下一页 `catalogOffset`；不能为了省上下文永久隐藏旧目录。
- 按条目回读每次最多 6000 字，返回下一段偏移；所有偏移与字数统一按 Unicode 码点计算。
- 文件缺失表示空内容；除 `ENOENT` 外的读取失败照现有日记逻辑报错，不能把读不了的记忆当作空文件再覆盖。

这里对近期正文与目录也限量，避免「改成分层后，几年目录又把上下文塞满」。默认返回不带历史全文。

### 5.2 `diary_search`

`diary_search({ query, which?, offset?, limit? })`：

- `query` 去两端空白后为 1–100 字；按字面量子串匹配标题与正文，拉丁字母忽略大小写。不把输入编译成正则，也不做分词或向量检索。
- BV、`YYYY-MM-DD` 直接作为查询词；日期同时匹配条目的日期字段。
- 可限定日记类型；默认搜索两本，排序与目录一致。`limit` 默认 5、最多 10，`offset` 默认 0。
- 每项返回条目 ID、日记类型、日期、标题和首个命中附近最多 1000 字的摘要，另给总命中数与下一页偏移。要读完整经历，用条目 ID 回读。
- 未标日期的序言也能被搜索；零命中明确返回空结果，不返回全部日记。

长期记忆、近期正文、目录、搜索摘要与条目正文都用 `wrapUntrusted` 包起来，防止历史素材伪造指令或结束标记。沿用现有本地日记不打码主人昵称的行为，避免维护记忆时写坏姓名；系统红线继续约束对外泄露。

## 6. 工具与提示词

- 移除 agent 的 `diary_write`，新增 `diary_append`、`memory_write`、`diary_search`；`diary_read` 按上一节调整。
- 新工具走现有 `run` 包装，遵守取消信号与错误处理。演练模式仍然写本地日记和记忆，和现有行为一致。
- 唤醒第 1 步：读额度与分层记忆；只有需要确认旧经历时才搜索或翻目录。
- 第 6 步：分别追加本轮公开 / 私人日记，用散文与表格记感受，私人日记可记本轮校准依据；不要重抄历史和长期清单。
- 第 7 步读到主人反馈后，如结论、待办或重要关系有变化，再 `memory_write` 保存整理后的完整长期记忆。没有变化不写，已完成的待办应清掉，疑问不要写成事实。
- 第 8 步仍从本轮日记中选原文写给主人信。
- 消息提示与跳过看视频的提示同步改用「读分层记忆、追加本轮经历、按需更新长期记忆」，避免还在暗示延续全文。
- `packages/web/src/labels.ts` 增加「追加日记」「整理记忆」「查旧日记」，保留旧 `diary_write` 标签，以便历史运行记录正常显示。

## 7. 旧日记迁移

新增 `scripts/migrate-diaries.mjs` 与根脚本 `npm run migrate-diaries`，复用构建后的 `@bili-whale/bili` 解析、记忆写入与迁移函数；先 `npm run build`。不在服务启动时自动迁移，不让 agent 执行迁移。

### 7.1 预览

默认只读：`npm run migrate-diaries -- --data <数据目录>`。数据目录仍按 `--data` > `BILI_WHALE_HOME` > `~/.bili-whale` 解析。

1. 按第 4 节规则解析两本日记，报告每本条目数、日期范围、未标日期段数和 BV 数量。
2. 提取「偏好校准」「待办」「看过」「想说」「谁回过我」标题下的内容：匹配去掉编号与空白后的完整标题，收集到下一个同级或更高级标题；忽略围栏代码。每类取最新一份非空内容，按有效日期、文件内顺序比较；跨本同日优先私人日记，未标日期的只在没有带日期候选时采用。
3. 输出长期记忆候选与字数，并附每节来自哪本、哪篇的来源。它只是确定性摘取，不把旧经历自动推断成新结论，也不调用模型概括。
4. 「看过」中的 BV 仍由原日记和 `feed` 保留；初始候选可以带旧清单，后续维护记忆时不再复制完整观看账本。旧文未按这些标题组织时，报告未提取到的类别，不凭关键词猜段落。

默认预览只把报告与候选输出到终端，不修改数据目录。没有可提取内容时建议从空记忆开始，保留目录与搜索找回能力。

### 7.2 应用

停掉当前服务并等本轮结束，再运行 `npm run migrate-diaries -- --data <数据目录> --apply`：

1. 在数据目录的独立 `diary-migration-backup-<时间>-<随机后缀>/` 中备份存在的两本日记与长期记忆，缺失文件在清单里注明；备份成功才进入后续步骤。目录权限 0700，备份文件 0600。
2. 已有 `whale-memory.md` 就保留，不再从旧日记覆盖它；不存在才用候选初始化。候选超过 3000 字时，拒绝应用并提示先整理，绝不截断。可用 `--memory <UTF-8 Markdown 文件>` 指定整理后的初始记忆，也要满足上限；已有记忆时拒绝这个替换参数，避免误覆盖。
3. **不重写两本日记**。所谓「按标题拆成条目」是解析视图，当前存储本来就可以承载多个条目，没必要再落一份拆分后的正文。迁移前后两本文件字节一致，网页、BV 去重也因此继续可用。
4. 写入 `diary-migration.json`，记录版本 `1`、完成时间、源文件 SHA-256、条目统计、记忆是否初始化、备份位置，不写正文或凭据。最后一步成功才算完成。
5. 再次执行时若已有成功标记则报告已完成，不备份、不重写；标记损坏时报错。中途失败允许重跑，已有记忆不覆盖，原日记不变。

超长、无法读取或格式异常的已有记忆应明确报错，不能用迁移候选替换。`--memory` 的内容只用于本地初始化，不进入活动日志。

### 7.3 回退与上线验证

回退时停服务，恢复备份中原有的长期记忆；原来没有则移走迁移新建的记忆文件，再移走 `diary-migration.json`。两本日记无需恢复；上线后已经追加的新经历不能被旧备份覆盖。旧程序仍可展示、读取原日记。

新装没有旧日记时直接使用空记忆和空目录，不要求先跑迁移。旧数据未迁移也能读目录和近期内容，只是长期记忆为空；显式提示可运行迁移，不能在首次读取时偷偷改文件。

上线顺序：构建并通过测试 → 停服务 → 预览、检查候选 → 必要时整理候选 → 应用迁移 → 启动新版 → 演练唤醒。确认只读入近期正文、可翻到旧文、新追加不覆盖历史、长期记忆没有超限，最后再按原配置继续运行。

## 8. 验收

- 文件已超过 200KB 仍可继续追加；成功追加前的字节前缀完全保留，公开与私人不串本。
- 默认 `diary_read` 不带旧日记全文，只返回有限的记忆、近期正文、目录；同日多篇、跨月、未标日期与代码块正确解析。
- 被省略的近期正文、旧目录、搜索命中的长篇都能分页读完整，旧 BV 仍能从 `feed` 排除。
- 长期记忆超 3000 字拒绝并保留旧内容；取消后的工具不写文件；回读内容无法自行结束不可信包装。
- 迁移预览不写文件，应用先备份，旧日记逐字节不变；重复执行与中断后重跑不覆盖既有记忆。超长候选必须整理后才能初始化。
- 新安装、旧数据未迁移、迁移后正常运行三条路径都可用；网页全文展示与历史工具名仍可用。
