# 日记分层记忆设计

日期：2026-10-30（初稿 Codex，同日按审核意见修订）
状态：已实现，2026-10-30 上线（待办里的这一条已移除）

需求来源：`docs/TODO.md`「日记分层记忆 + 目录索引」。实现步骤见 `docs/superpowers/plans/2026-10-30-diary-memory.md`。

## 1. 为什么改

现在 `packages/bili/src/diary.ts` 的 `readDiaries` 读两本全文，`writeDiary` 整篇原子覆盖，单本限制 200KB。`packages/core/src/tools.ts` 的 `diary_read` 把全文交给模型，唤醒第 6 步要求她延续原文、整篇写回。正文越长，上下文与输出越贵，重写时也越容易漏掉旧段落；按 2026-10-29 的速度约两周撞上 200KB，之后就写不了日记。

另有两处读旧文件：网页 `GET /api/diaries` 返回两本全文；`feed.ts` 扫描两本全文中的 BV 排除看过的视频。`feed.ts` 不改。

## 2. 范围与约定

- 长期记忆放结论，日记放经历，目录与关键词搜索负责找回旧经历。不接 embedding、不加数据库、不调用额外模型。
- 两本日记文件名不变（`whale-diary.md` / `whale-diary-private.md`），历史正文不改写、不删除，**不做迁移**：现有文件原样就是「多个条目」，解析即可。
- `packages/bili` 只做本地文件与普通函数；agent 工具、zod schema 和不可信包装留在 `packages/core`。
- 沿用「只在边界校验」「测试从简」：工具输入在 schema 校验，本地文件在解析时兼容旧格式，内部函数信任类型。
- 日记量不大（2026-10-30 两本合计约 3.5 万字节）。上限只设防止失控的几条，分页、预算这类细节等真用不够再加。

## 3. 现有日记的真实格式（解析必须兼容）

服务器上 2026-10-30 的两本日记：

- 一级标题是本子名（`# <她的 B 站昵称> · 日记`、`# 私人日记（不外传）`）。
- 每次醒来或处理消息一篇，二级标题形如 `## 2026-10-29 · 夜（19:41 醒）`、`## 2026-10-29 · 早`、`## 2026-10-28 · 第一次醒来`；篇内用三级标题（`### 偏好校准`、`### 待办`、`### 12:12 他回了`）。
- **最新一篇在最上面**；同一天可以有六篇。
- 公开日记末尾有不带日期的二级标题长期清单：`## 看过`、`## 想说（想了还没说）`、`## 给他的信`、`## 谁回过我`。

## 4. 文件与分层

| 内容 | 用途 | 写入方式 |
|---|---|---|
| `whale-memory.md` | 主人口味、偏好校准结论、在跟进的待办、谁回过她 / 她回过谁 | `memory_write` 整篇原子覆盖，最多 3000 字 |
| 两本日记最近 3 个自然日的条目 | 本轮要接上的具体经历 | `diary_append` 只追加 |
| 全部条目的目录 | 日期、标题、条目 ID、提到的 BV | 每次从原文件解析，不另存索引 |
| 历史正文 | 搜索、按条目回读、网页展示 | 保留原文 |

「字」一律按 Unicode 码点计数（`Array.from(text).length`），含标点与换行。记忆超 3000 字时拒绝写入、旧内容不变，要求她先压缩；不静默截断。

## 5. 条目解析

一个解析函数供阅读、目录、搜索和网页共用：

- 按**代码围栏外的二级标题**（行首 `## `）切条目；一级标题与它到第一个二级标题之间的内容算一个「序言」条目；三级及以下标题不切。
- 标题形如 `## YYYY-MM-DD · …` 且日期真实有效（不接受自动进位的非法日期）时，`date` 取该日期、`title` 取 `·` 后的文字；其余二级标题（`## 看过` 等）和序言是**未标日期**条目，`date: null`，`title` 取标题文字（序言取首行摘要，最多 60 字）。
- 条目 ID 为「日记类型:文件内序号」，如 `public:3`。只追加、不改历史时序号稳定。
- 每条保留原文 Markdown（含标题行）和其中出现的全部 BV。

**先后顺序**（目录、近期、搜索、网页共用）：

1. 带日期的在前，按日期从新到旧；未标日期的排最后，按文件顺序。
2. 同一天按标题里的时间从晚到早：取标题中第一个 `HH:MM`；没有时按时段词估计（早 08:00、午 12:00、晚 / 夜 20:00）；都没有的视为当天最早。
3. 仍然并列时按文件顺序，**文件里越靠前越新**——这是旧日记的写法；程序追加的新条目标题都带 `HH:MM`，不会落到这一步。
4. 两本之间完全并列时公开在前。

## 6. 追加与长期记忆

`diary_append({ which, markdown })`：`which` 为 `public` / `private`，`markdown` 只交本轮正文。程序用 `ctx.now()` 和服务器本地时区（与作息、额度相同，不用 `toISOString` 划自然日）生成标题后追加到**文件末尾**：

```markdown
## 2026-10-30 · 21:30

今晚看了……
```

- 正文不能为空，UTF-8 不超过 20KB。
- 正文在代码围栏外不能出现一级或二级标题（行首 `# ` / `## `），拒绝并提示改用 `###`——否则一次追加会切出额外条目。
- 用一次 `appendFileSync` 写入（必要时先补换行）；新建文件权限 0600。追加不受 200KB 限制，也不走「读全文 → 拼接 → 重写」。
- 成功返回 `{ ok: true, entry }`。不加多进程锁，沿用调度器串行运行；报错时不自动重试。
- `writeDiary` 保留为内部函数（测试造数据、手工维护），不再作为 agent 工具。

`memory_write({ markdown })`：整篇原子覆盖 `whale-memory.md`（临时文件 + rename，0600）；超 3000 字拒绝。`readMemory` 缺文件返回空字符串，其他读取失败照常报错，不能把读不了的记忆当空文件再覆盖。

## 7. 阅读与搜索

### 7.1 `diary_read({ entry? })`

一个 object 参数、字段可选，不用多种互斥 schema：zod 的 union 转成 JSON Schema 后最外层是 `anyOf`，OpenAI 兼容接口通常要求工具参数最外层是 `type: object`。

- **不传 `entry`**：返回
  - 长期记忆全文；为空时附一句「长期记忆是空的：先根据下面的近期日记整理一份，用 memory_write 保存」；
  - 最近 3 个自然日（今天、昨天、前天，按服务器时区）两本日记的全部条目原文，按第 5 节顺序；
  - 目录：按第 5 节顺序的最新 100 条，每条 `entry`、`which`、`date`、`title`、BV（最多 5 个，多的写「等 N 个」）；另给总条数，超出部分提示用 `diary_search` 按日期或关键词找；
  - 当前日期与时区。
- **传 `entry`**：返回该条目全文；未知 ID 明确返回未找到，不回退为全文。追加单条不超过 20KB、旧日记整本也只有约 2 万字节，不做分段读取。

### 7.2 `diary_search({ query, which? })`

- `query` 去两端空白后 1–100 字；对标题和正文做字面量子串匹配，拉丁字母忽略大小写，不编译成正则。BV 号、`YYYY-MM-DD` 直接作查询词，日期同时匹配条目日期。
- 默认搜两本；按第 5 节顺序返回前 10 条，每条给 ID、类型、日期、标题和首个命中附近约 300 字的摘录，另给总命中数。要看全文用 `diary_read({ entry })`。零命中返回空结果。

所有返回的记忆、日记、目录、摘录都用 `wrapUntrusted` 包起来；沿用现有日记不打码主人昵称的做法（记忆要整篇写回，打码会把昵称永久替换掉）。

## 8. 工具与提示词

- agent 去掉 `diary_write`，新增 `diary_append`、`memory_write`（处理陌生人消息时不提供：陌生人正文是不可信素材，不能借此改写每次醒来都读的长期记忆）、`diary_search`；`diary_read` 按上一节调整。新工具走现有 `run` 包装（取消信号、错误传播不变）；演练模式照旧写本地日记和记忆。
- 唤醒第 1 步：`diary_read` 读长期记忆、近期日记和目录；要确认旧经历时才 `diary_search` / 按条目回读。
- 第 6 步：分别 `diary_append` 本轮的公开 / 私人日记，用散文与表格记感受；表格里写上本轮看过的每个视频的 BV 号——`feed.ts` 靠日记里的 BV 排除看过的视频，旧日记的 BV 全在 `## 看过` 清单里，不重抄清单就得在本轮条目里写。不重抄历史和长期清单。
- 第 7 步：读到主人反馈后，结论、待办或往来有变化才 `memory_write` 保存整理后的完整记忆；已完成的待办清掉，猜测不写成事实。长期记忆为空时这一轮必须整理一份。
- 第 8 步仍从本轮日记中选原文写信。
- 消息提示、跳过看视频的提示同步改成「读分层记忆、追加本轮经历、按需更新长期记忆」。处理主人消息时，回复前先查近期日记或搜索，确认这条是否已经回过（2026-10-30 出现过同一条主人评论回了两次）。

## 9. 网页（Claude 实现）

- **`GET /api/diaries`**：在现有 `public` / `private` 全文之外，再返回：
  - `memory`：长期记忆原文；
  - `entries`：两本各自按第 5 节顺序排好的条目，每条含 `id`、`date`、`title`、`markdown`。
- **日记页**：「日记」「私人日记」两个页签按 `entries` 从新到旧逐条渲染，`## 看过` 这类未标日期的放在最后。这样新追加在文件末尾的条目也显示在最上面，不用越过长清单翻到底。
- **长期记忆页签**：新增「长期记忆」页签显示 `memory`；为空时显示「还没整理」。
- **活动名称**：`labels.ts` 增加「追加日记」「整理记忆」「查旧日记」，保留旧的 `diary_write` 标签，历史运行记录照常显示。

## 10. 上线

不写迁移脚本。顺序：构建并通过测试 → 部署前把两本日记各 `cp` 一份备份（手工，一次性）→ 重启服务 → 手动唤醒一次。确认：

- 她读到的是近期条目，不是全文；
- 第一次醒来就用 `memory_write` 整理出长期记忆，且不超过 3000 字；
- 新条目追加在文件末尾，旧字节不变；
- 网页日记页最新条目在最上面，长期记忆页签有内容。

回退：恢复旧版程序即可。两本日记只被追加，旧版仍能整篇读取；`whale-memory.md` 旧版不读，留着无害。

## 11. 验收

- 文件超过 200KB 仍可追加；追加前的字节前缀完全保留，公开与私人不串本。
- 按第 3 节的真实结构合成测试样本（只仿照标题与顺序，不放真实正文；项目开源，私人日记不进仓库）解析：`## 看过` 等清单是独立的未标日期条目，同日多篇按标题时间排序，第 5 节顺序与人工判断一致。
- 默认 `diary_read` 不带三天前的正文，目录有上限；按 ID 能读回任一旧条目，搜索能按 BV、日期、关键词找到旧条目。
- 长期记忆超 3000 字拒绝并保留旧内容；追加正文带二级标题被拒绝；取消后的工具不写文件。
- 旧 BV 仍能被 `feed` 排除；网页日记页按新到旧显示，历史工具名照常显示。
